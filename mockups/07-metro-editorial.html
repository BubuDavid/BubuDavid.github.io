    01

    Case studyp. 06

    Backend & AI lead · 2024 – now

    Pulso

    A KPI copilot that lives in Microsoft Teams. It warns leaders before a number misses, helps them find out why, and checks whether the fix worked.

    Grew from Socorro Bot, a WhatsApp bot that guided families through missing-person reports. Archive Nº 01, p. 34

    i.Problem

    Leaders learned a KPI had slipped weeks late, diagnosed it by hand in spreadsheets, and nobody checked whether the fix worked.

    ii.Approach

    A Teams bot and tab. People ask about company data in plain language. Pulso sends an alert when a KPI drifts off its trajectory, before it misses, and lets the team open an action plan with an owner, a date and a budget.1

    iii.Outcome

    On the due date Pulso gives its own verdict. It compares the office with its peers to separate real wins from market-wide effects. It now has 1,400 weekly users across 3 companies and has verified 312 action plans.

    02

    Case studyp. 14

    Creator · 2025

    Lienzo

    Dashboards that design themselves from one question. The model plans the page and Python does the arithmetic.

    Grew from Spotify Analysis, personal insights from your top 50 songs. Archive Nº 04, p. 37

    i.Problem

    Each new question from leadership meant someone had to build a dashboard by hand. Asking a language model directly was faster, but nobody could trust the figures it wrote.

    ii.Approach

    A planner model reads one question and designs the layout. Parallel workers fill each widget with queries over the semantic layer.2 Python computes every number. The model never writes one.

    iii.Outcome

    A question becomes a dashboard in about 40 seconds, built from 9 widget types. An audit of 500 answers found 0 hallucinated figures.

    03

    Case studyp. 22

    Core engineer · 2024 – now

    Glosa

    A semantic layer, as code. Business questions go in, and SQL for Postgres, Snowflake or Microsoft Fabric comes out.

    Grew from Bubufy, a small Python library over Spotify's API. It was my first API designed for other people. Archive Nº 08, p. 41

    i.Problem

    Every client defines its metrics, hierarchies and business rules a little differently. Engineers rewrote the same questions by hand for whichever database the client ran, and onboarding a new client took six weeks.

    ii.Approach

    A CLI and an API compile business questions into SQL for three engines. Each client's metrics, hierarchies and rules live in a versioned git repository, and an Explorer UI lets the team browse and test them.3

    iii.Outcome

    Client onboarding dropped from 6 weeks to 4 days. The layer holds more than 180 metric definitions, and each one compiles for Postgres, Snowflake and Microsoft Fabric.
